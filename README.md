# mywebview

プレゼン用 webview。複数モニターにまたがる枠なしウィンドウに Web ページ（または指定の exe）を表示し、別モニターのコントロールパネルから操作する Electron アプリです。

## 機能

- 指定した位置・サイズ（既定: x=1280, y=0, 3840×720 = 1920×1080@150% のモニター 3 枚分）に枠なしで表示
- URL の代わりに exe を指定すると、起動したアプリのウィンドウを枠なしにして同じ位置・サイズに置く（Windows のみ。[exe の表示](#exe-の表示)）。複数の exe を起動したまま切り替えられる
- コントロールパネル
  - 表示中の URL（exe）の表示・入力（Enter で移動）
  - `url_list.txt` に登録した URL・exe の一覧（クリックで表示）
  - 縮小プレビュー（16:9 ごとの区切り線付き）。プレビュー上でマウス・キーボード操作も可能。モニターに表示しているとき（実表示で表示領域がモニターに収まるとき）は、起動時はプレビュー OFF（ボタンで ON にできる）。疑似表示では常に ON で起動し、疑似表示に切り替えたときも ON にする
  - 疑似表示 ⇔ 実表示 の切り替え
  - 画面を消す: 表示領域を最前面の黒いウィンドウで覆う（Web ページ・exe のどちらの上にも出る）。消している間もプレビューには裏の内容が映る。疑似表示中は使えない
- 疑似表示: 表示領域がモニターに収まらないとき（外部モニターが無い等）は、画面に出さずにオフスクリーンで描画し、プレビューだけで確認・操作できる
- スクロールバーは非表示（ページのレイアウト幅を指定幅のままにするため）

## 使い方

```sh
npm install
npm start                                   # 既定の URL・位置・サイズで起動
npm start -- https://example.com --x 1280 --y 0 --w 3840 --h 720
npm start -- "C:\Program Files\Example\app.exe"   # exe を表示（Windows のみ）
npm test                                    # exe の指定の解析などを確認
```

| オプション | 説明 |
|---|---|
| `URL` | 最初に表示する URL（既定: `https://www.google.com/`）。スキーム省略時は `https://`。exe のパスも指定できる |
| `--x`, `--y` | 表示位置 |
| `--w` / `--width`, `--h` / `--height` | 表示サイズ |
| `--virtual` | 疑似表示で起動（モニターに出さずプレビューのみ） |
| `--real` | 実表示で起動（モニターに収まらなくても表示） |
| `--debug` | 起動時に指定値・実際の位置・ディスプレイ情報を表示 |

座標・サイズは DIP（表示倍率で換算後の値）です。150% 表示の 1920×1080 モニターは 1280×720 として扱われます。

### url_list.txt

1 行に 1 件、`表示名, URL` の形式で書きます。`#` で始まる行はコメントです。

```
google, https://www.google.com/
yahoo japan, https://www.yahoo.co.jp/
ビューア, "C:\Program Files\Example\viewer.exe" --fullscreen "D:\資料\a b.pdf"
ツール, tools\tool.exe
```

URL の代わりに `.exe` で終わるパス（後ろに引数を続けてよい）を書くと exe として扱います。

- パスは `\` かドライブ名（`C:` 等）を含めて書く（`example.com/setup.exe` のようなスキーム省略の URL と区別するため。同じフォルダーなら `.\app.exe`）
- パスに空白を含むときは `"..."` で囲む（引数も同じ。`/dir="C:\a b"` のような書き方も可）
- `%LOCALAPPDATA%` などの環境変数を使える（例: `ペイント, %LOCALAPPDATA%\Microsoft\WindowsApps\mspaint.exe`。ユーザー名を含むパスを PC ごとに書き換えずに済む）。未定義の変数はそのまま
- 相対パスは `url_list.txt` のある場所が基準（パネルの入力欄・コマンドラインで指定したときも同じ）

## exe の表示

exe を選ぶと、exe を起動し、そのウィンドウの枠を消して指定の位置・サイズに置きます。プレビューにはそのウィンドウのキャプチャを動画で表示します。

- 別の URL・exe に切り替えても、起動した exe は閉じずに最小化しておく（Web ページの表示用ウィンドウも閉じずに隠しておく）。起動中の exe を選ぶと、起動し直さずに前に出す
- 一覧では起動中の exe に「起動中」と「終了」ボタンが出る（入力欄から起動した exe も一覧の最後に出る）。上部の「アプリを終了」は前に出ている exe を閉じる
- 前に出ている exe を閉じると、1 つ前に表示していたもの（URL または起動中の別の exe）に戻す
- 閉じるときは強制終了ではなく通常の「閉じる」なので、保存の確認などはアプリ側で出る。キャンセルされたら起動中のまま。背面の exe で保存の確認などが出た場合は、前に出して操作する
- アプリ側の閉じるボタン等で閉じられた場合も、終了として扱う（起動から 30 秒以内は、スプラッシュ画面の後の本体のウィンドウを待つ）
- mywebview を終了すると、起動中の exe をすべて閉じる
- 起動した exe が別のプロセスを起動して終わるタイプ（ランチャー型）や、起動済みのアプリに処理を渡すタイプ（PowerPoint 等）でも、起動後に現れた新しいウィンドウを探して使う（起動後に始まったプロセスか、同じ名前の exe のウィンドウに限る）。スプラッシュ画面の後に本体のウィンドウが出る場合も追従する
- タイトルバーをアプリ自身が描いているアプリ（Windows 11 のメモ帳・ペイント、Chrome、Office 等）は、枠を外すとアクティブになったときに表示が崩れ、外してもタイトルバーは消えないため、自動で見分けて枠は外さない。見えている範囲を指定の位置・サイズに合わせる（アプリのタイトルバーや最小化・閉じるボタンは表示されたまま。Windows 11 では角が丸く、細い縁取りが出ることがある）
- 配置後しばらく（5 秒）は、アプリ側で位置・サイズを戻されても合わせ直す。枠を外したアプリで枠が付け直されたら外し直す。最大化されたら（タイトルバーのダブルクリック等）元に戻す
- 疑似表示はできない（常に実表示）。表示領域がモニターに収まらないときは警告を出す
- プレビュー上のマウス操作はウィンドウに直接メッセージを送る方式（実際のカーソルは動かない）。クリックすると exe のウィンドウがアクティブになり、以降のキー入力は exe が直接受け取る（パネルに戻すにはパネルをクリック）

上手くいかない場合があるもの:

- ウィンドウのサイズを自分で決めて変更を受け付けないアプリ
- 管理者権限で動くアプリ（mywebview から操作できない）
- 排他フルスクリーンのゲームや、画面キャプチャを禁止しているアプリ（プレビューが黒くなる）
- DirectX・Raw Input を使うアプリ（プレビュー上のマウス操作が効かない）
- 最小化中（プレビューが映らない）
- 既に起動中のウィンドウを再利用するアプリ（新しいウィンドウが見つからない）

## Windows 用 ZIP の作成

```sh
npm run dist:win    # → dist/mywebview-<version>-win.zip
```

ZIP の構成:

```
url_list.txt
mywebview.bat   … これを起動（引数はそのまま渡される）
apps\           … アプリ本体
```

Linux 上でビルドできます（Wine は不要）。exe 表示に使う koffi の Windows 用バイナリは、ZIP 作成時に npm から取得して `apps\resources\koffi\` に入れます。

## リリース手順

1. `package.json` の `version` を上げてコミット・push
2. ZIP を作成: `npm run dist:win`
   - `package.json` はアプリ本体に含まれるため、`package.json` を変更したら（メタデータだけでも）ZIP を作り直す
3. Release を作成して ZIP を添付:
   ```sh
   gh release create vX.Y.Z dist/mywebview-X.Y.Z-win.zip --target main --title vX.Y.Z --notes "..."
   ```
